# Verify skill: tvlog

## What this app is

**tvlog** — a personal TV log on atproto (AT Protocol). TV-only: you search and log TV shows; there is no movie search or movie logging in the UI. Logging-first: the signed-in home leads with the shows you're currently watching, each with its next unwatched episode ready to log in one tap; free-form tags matter more than ratings. Users authenticate with their atproto identity; records are written to their own PDS. (The domain is still log.sims.computer, but the app calls itself "tvlog" everywhere user-visible.)

## Authenticating (do this first for any logged-in surface)

Navigate to `/api/auth/test-login`. If test credentials are configured in this environment (they are in preview), this establishes a session as a dedicated test account and redirects to `/`. Confirm success: the top-right of the header shows a **round profile icon** (not a "Sign in" link), and a **round search button (FAB) appears fixed at the bottom-right** of the screen.

- If `/api/auth/test-login` returns 404, test credentials are absent — verify only logged-out surfaces and note the limitation.
- **Never attempt the OAuth sign-in path** (`/login` → the primary handle form). It redirects off-origin to a PDS and requires human consent; off-origin traffic is invisible to you and the flow cannot complete. Checking that `/login` renders the form is all that's possible.
- The "app password" disclosure on `/login` posts same-origin and would work, but you don't have credential values — use `/api/auth/test-login` instead.
- Writing data while authenticated is safe and expected: everything lands in the throwaway test account's PDS, not a real user's.

## Surfaces

- `/` — **logged out**: the landing page — the "tvlog" wordmark, the tagline "a personal TV log", and a prominent "Sign in" button linking to `/login`. There is **no search access when logged out** (search uses a personal TMDB key). **Signed in**: a **watching-first home**, not the full diary.
  - Beside the **"Watching"** heading is a small **"Watchlist"** link/pill that navigates to `/watchlist`.
  - It leads with a **"Watching"** section (an `h1` reading "Watching") — a grid of cards for the shows currently in progress that **have a next unwatched episode ready to log**, most recent activity first, capped at a sensible number (~12). Each card shows a **poster** (loaded same-origin through `/_next/image?...`), the **show title** (a link to `/show/<tmdbId>`), a **next-episode line formatted "Next · S<n>E<m>"** followed by the **episode's title** (long titles truncate to one line), and a round **checkmark log button**. The checkmark button has **no visible text**; its accessible name is **"Log S<n>E<m>"** (e.g. `aria-label="Log S2E3"`). Tapping it opens the **log sheet preloaded with that exact next episode** (the same no-picker sheet described below, with "Just Finished" preselected) — one tap on the sheet's "Log watch" submits. After a successful log, the home re-renders and **that card advances to the following episode**; if that was the finale (the show becomes caught up), the card **drops out of the grid** on refresh.
  - **Caught-up shows are not shown here at all.** A show with every aired episode already watched has nothing to log next, so it is filtered out of the Watching grid entirely (it is not hidden data — it still appears in the diary / on its show page). There is no per-card "caught up" state.
  - Below Watching is a compact **"Recent"** section (an `h2` reading "Recent") — the diary grouped by day, newest first, each entry with title, optional season/episode, tag chips, optional note, and a rewatch marker. A TV entry's **title links to its show page** (`/show/<tmdbId>`); older imported movie entries render as plain text with no link. The Recent section is omitted entirely when there is no watch history.
  - **Empty states** (either replaces the card grid; the Recent section still shows below if there's history): if the account has **no shows in progress at all**, a panel reads **"Nothing in progress yet."**; if it has in-progress shows but **every one is caught up**, the panel instead reads **"You're all caught up."**. Both offer a **"Search shows"** link pointing at `/search` — no error, no blank section. (The test account normally shows cards, not either empty state.)
- **Header (signed in)** — top-right is a single round **profile icon** (aria-label "Account menu"). Clicking it opens a small popover menu containing a **"Log out"** button. There is no visible handle/username and no "Log a watch" button anywhere.
- **Search FAB (signed in)** — a round floating action button fixed at the **bottom-right** (aria-label "Search") with a magnifying-glass icon. It is the only entry point to search; tapping it navigates to `/search`.
- `/search` — **signed in only**. If visited while logged out, it shows a "Sign in to search" prompt with a Sign in link rather than a search box. When signed in: a TMDB-backed **TV-only** search. The input is debounced (~300ms): after typing, wait for the grid to update before judging results. Posters must load through `/_next/image?...` on this origin — a visible poster implies the same-origin rule held. Nonsense queries show a no-results state, not an error. There is **no movie/TV filter toggle** (results are always TV shows). Result cards have **no "Log" button**: the whole card is a link — tapping a result navigates to that show's page at `/show/<tmdbId>`.
- `/show/<tmdbId>` — **the show page** (signed in; reachable from a search result tap, a Watching card, or a diary entry). Server-rendered for a TV show: a small **history-aware back control at the top reading "← Back"** (it returns to wherever you came from — the home or search — via browser history, falling back to home on a direct load; it is **not** labelled "Search"), then backdrop/poster, title, year, and overview, followed by a **"Seasons"** list. Season 0 / specials, if present, sort to the end. Each season is a button that **expands to reveal its episodes** (episode number + name), fetched same-origin from `/api/tmdb/season?show=<id>&season=<n>` — the browser must never call TMDB directly here either. Each episode row has a compact **"Log"** button. Tapping it opens the **log sheet** with the show, season, and episode **already chosen from context**: the sheet has **no season/episode picker** — it shows what's being logged as static text (title, then `S<n>E<m> · <episode name>`). Submitting writes records to the test account's PDS — logging during verification is safe and expected. Guard: a season with no episodes shows an empty state, not an error; season data loads must not 404.
  - **Watchlist button** (signed in): near the title the page shows a watchlist control whose state depends on where the show already sits. A show on **neither** list shows an **"Add to Watchlist"** button; clicking it adds the show and the button flips in place to **"On Watchlist"** (clicking again removes it, back to "Add to Watchlist") — no reload needed. A show **already being watched or fully watched** shows a plain non-interactive **"Watching"** / **"Watched"** badge instead, and **no** add/remove button (correct, not a failure). The test account has watched many shows, so expect the badge on those; pick a show it has never logged to see the "Add to Watchlist" button.
- `/watchlist` — **signed in only**; the destination of the home "Watchlist" link. If visited while logged out, it shows a **"Sign in for your watchlist"** prompt with a Sign in link rather than a grid. When signed in: an `h1` reading **"Watchlist"** above a **poster grid** of the shows on the watchlist (those in the account's `tv_show_watchlist` list). Each poster links to that show's page at `/show/<tmdbId>` and carries a small round **remove** button (aria-label "Remove … from watchlist") at its top-right corner that drops the show from the grid in place. With an empty watchlist it shows a **"Nothing on your watchlist yet."** panel with a **"Search shows"** link to `/search`, not a blank page or error.
- **Watchlist → watching transition**: logging the first episode of a show that's on the watchlist moves it off the watchlist and into the Watching set. After adding a never-watched show to the watchlist and then logging one of its episodes (from its show page), that show leaves `/watchlist` and appears on the home "Watching" grid — it is never in both at once, and no duplicate card appears.
- **The log sheet** — on a phone viewport it presents as a **bottom sheet** that slides up from the bottom edge (full-width, rounded top corners, a small drag-handle bar at the top, safe-area aware); on a desktop-width viewport it is a centered dialog instead. Backdrop tap, the top-right **× "Close"** button, and the Escape key all dismiss it. The sheet leads with a two-option segmented control (role `radiogroup`, aria-label "When did you watch this?") of **"Just Finished" | "Other"**. **"Just Finished" is preselected** and is the fastest path — it logs the current moment, so one tap on the prominent full-width **"Log watch"** button at the bottom submits immediately with no further input. Choosing **"Other"** reveals a **wheel date picker** (see below). Tags, a note, and a rewatch checkbox are secondary, tucked behind an **"Add tags or a note"** disclosure that expands when tapped. There is **no `<input type=date>`** and **no calendar grid** anywhere.
- **The wheel date picker** (only visible after tapping "Other") — three side-by-side scrollable columns, **Month** (e.g. "Aug"), **Day** ("12"), **Year** ("2026"), iOS-rotary style: each column (role `listbox`, aria-labels "Month" / "Day" / "Year") is a scroll-snap list whose selected value sits in a highlighted center band, with values above/below dimmed and faded at the edges. A value can be selected either by **scrolling the column** (touch, mouse-wheel, or drag) **or by clicking a visible value** (it scrolls to center). Above the columns a live line shows the resolved date **with weekday**, formatted like **"Wednesday, August 12, 2026"**, updating as the selection changes. The day column clamps to the month's length (switching to a short month snaps an out-of-range day down). It defaults to today; the year range runs 2000..current year. Scrolling must not spam network requests or the console — the verify bar expects **zero console errors** and no failed requests.
- **Tag chips link to `/tags/<tag>`, which is not implemented yet** — it 404s by design in this slice. Don't click tag chips while judging console cleanliness, and don't report the 404 as a failure.
- `GET /api/auth/session` — always 200: `{authenticated: true, did, handle}` or `{authenticated: false}`. (Deliberately not a 401 — a 401 on this probe pollutes the browser console on every logged-out page load.) `POST /api/auth/logout` clears the session.
- `/api/healthz` — liveness, `{"ok": true}`. `/api/diary`, `/api/log`, `/api/tmdb/title` back the diary and logging flows. `/api/tmdb/search` returns TV results only; `/api/tmdb/season?show=<id>&season=<n>` returns a season's episodes for the show page.

## App-specific gotchas

- All API traffic is same-origin by design (TMDB is proxied server-side; the API key must never appear in the browser). If the browser calls api.themoviedb.org or image.tmdb.org directly, that is itself a failure worth reporting. Posters are still optimized through `/_next/image?...` on this origin, but their upstream source varies: search and show-page posters come from image.tmdb.org, while Watching-card posters come from a stored blob on cdn.bsky.app — both are proxied, so the `/_next/image` request is same-origin either way.
- The favicon is `/icon.svg` (linked in head); a 404 for `/favicon.ico` in the console would be a regression.
- Target device is a phone: surfaces are verified at a phone viewport. Touch targets (profile icon, FAB, buttons) should be comfortably tappable.
